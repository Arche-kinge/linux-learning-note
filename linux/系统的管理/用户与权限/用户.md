Linux 的用户与权限，核心可以概括为：**用户/组决定“谁”，文件权限决定“能做什么”，sudo/ACL 等提供更细控制**。

## 1. 用户与组

### 用户
- **root**：超级用户，UID=0，几乎不受权限限制。
- **系统用户**：给服务/进程使用，通常 UID 1~999，不能登录或 shell 为 `/sbin/nologin`。
- **普通用户**：通常 UID 1000 起，可登录。

查看用户：
```bash
whoami          # 当前用户
id              # 当前用户 UID/GID/组
id alice        # 查看 alice
cat /etc/passwd # 用户信息
```

`/etc/passwd` 格式：
```text
用户名:x:UID:GID:描述:家目录:登录Shell
```

密码实际存放在 `/etc/shadow`，只有 root 可读：
```text
用户名:加密密码:最后修改:最小间隔:最大间隔:警告:失效:禁用:保留
```

### 组
- **主组**：用户默认所属组，在 `/etc/passwd` 第 4 字段。
- **附加组**：额外加入的组，在 `/etc/group` 中列出。

```bash
groups alice          # 查看用户所属组
cat /etc/group        # 组信息
```

### 常用用户管理命令
```bash
sudo useradd -m -s /bin/bash alice   # 创建用户并建家目录
sudo passwd alice                    # 设置密码
sudo usermod -aG sudo alice          # 加入 sudo 组，Ubuntu/Debian
# RHEL/CentOS 常用 wheel 组：sudo usermod -aG wheel alice
sudo userdel -r alice                # 删除用户及家目录
sudo groupadd dev                    # 创建组
sudo gpasswd -a alice dev            # 把用户加入组
```

注意：`usermod -aG` 必须带 `-a`，否则会覆盖原有附加组。

## 2. 基本权限模型

`ls -l` 输出：
```text
-rwxr-xr-- 1 alice dev 1024 Jan 1 file
```

拆解：
- 第 1 位：文件类型  
  `-` 普通文件，`d` 目录，`l` 符号链接，`c` 字符设备，`b` 块设备，`s` socket，`p` 管道。
- 接下来 9 位分三组：
  - `rwx`：所有者权限 u
  - `r-x`：所属组权限 g
  - `r--`：其他人权限 o

权限含义：

| 权限 | 对文件   | 对目录                   |
| ---- | -------- | ------------------------ |
| r    | 读取内容 | 列出目录项               |
| w    | 修改内容 | 创建/删除/重命名文件     |
| x    | 执行     | 进入目录、访问目录内文件 |

目录的 `x` 很关键：没有 `x`，即使有 `r` 也只能看到名字，不能进入或访问文件内容。

### chmod
符号法：
```bash
chmod u+x file       # 所有者加执行
chmod g-w file       # 组去掉写
chmod o=r file       # 其他人只读
chmod a+r file       # 所有人可读
```

数字法：`r=4, w=2, x=1`
```bash
chmod 755 file       # rwxr-xr-x
chmod 644 file       # rw-r--r--
chmod 600 file       # rw-------
chmod 700 dir        # rwx------
```

### chown / chgrp
```bash
sudo chown alice file
sudo chown alice:dev file
sudo chown -R alice:dev /data
sudo chgrp dev file
```

### umask
控制新建文件和目录的默认权限：
```bash
umask
```
常见：
- `umask 022`：新文件 `644`，新目录 `755`
- `umask 027`：新文件 `640`，新目录 `750`

## 3. 特殊权限

| 权限   | 数字 | 作用                                           | 示例              |
| ------ | ---- | ---------------------------------------------- | ----------------- |
| SUID   | 4    | 执行时以文件所有者身份运行                     | `/usr/bin/passwd` |
| SGID   | 2    | 执行时以文件所属组运行；目录中新文件继承目录组 | 协作目录          |
| Sticky | 1    | 目录中只有文件所有者/目录所有者/root 可删除    | `/tmp`            |

```bash
chmod 4755 file      # SUID
chmod 2755 dir       # SGID
chmod 1777 /tmp      # Sticky
```

显示为：
```text
rwsr-xr-x
rwxr-sr-x
rwxrwxrwt
```

## 4. 提权：su 与 sudo

```bash
su - alice           # 切换到 alice，并加载其环境
sudo command         # 以 root 执行单条命令
sudo -i              # 进入 root 登录 shell
sudo -l              # 查看当前用户可执行的 sudo 命令
```

配置 sudo 用：
```bash
sudo visudo
```
或写入 `/etc/sudoers.d/`：
```text
alice ALL=(ALL:ALL) ALL
%sudo ALL=(ALL:ALL) ALL
```
Ubuntu/Debian 常用 `sudo` 组，RHEL/CentOS 常用 `wheel` 组。

## 5. ACL 更细粒度权限

当 basic 的 u/g/o 不够用时，用 ACL：
```bash
setfacl -m u:bob:rw file      # 给 bob 读写
getfacl file                  # 查看 ACL
setfacl -x u:bob file         # 删除 bob 的 ACL
```

目录默认 ACL：
```bash
setfacl -d -m u:bob:rwx dir
```

## 6. 安全实践

- 遵循最小权限原则，慎用 `chmod 777`。
- 日常用普通用户，管理时用 `sudo`。
- 禁用不必要的系统用户登录。
- SSH 禁用 root 远程登录，优先用密钥。
- 定期检查 `id`、`groups`、`sudo -l`、`last`、`who`。
- 对敏感文件使用 `600`、`640`，敏感目录使用 `700`、`750`。
